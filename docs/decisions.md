# 設計判断

## 2026-11-24 新プロジェクトへの移行

TERRIFの旧個人サイトを廃止し、同じリポジトリで「満員電車（仮）」を開発する。旧ソースと固有文書は削除し、Git履歴を保持する。開発規約と汎用エージェント設定は継続利用する。

ユーザーは初期企画の承認段階で、目的を快適輸送からカオスへ変更した。現在の主目的はストレス連鎖によるトラブルの件数・種類・組合せでカオススコアを増やすこと。ストレス量そのものは得点にしない。5種族と年代は共通の属性へ合成する。イベントは通常50種＋特殊10種を初期実装対象とする。

TypeScript＋Vite、DOMとSVG、Web Audioを用いる。UIと純粋なゲーム評価を分離し、同一の因果ログを予告・本番・演出に使う。盤面座標を正本とし、固定シードで乗降と属性を再現する。BGMは独自の16bitサンプルベース楽曲とし、既存曲は使わない。

車両寸法・年代分布・実際の乗降とイベント頻度は検証済み事実とゲーム仮定を区別する。外部資料の取得制限はtrain-research.mdに記録する。具体的なルールと数値の正本はtrain-plan.md / train-events.md、体験設計はtrain-experience.md。
