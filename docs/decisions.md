# 設計判断記録 (ADR)

設計判断、採用理由、変更履歴を記録する。新しいエントリは末尾に追加する（古い順）。

## 記録フォーマット

```
## D-XXX: タイトル

- 日付: YYYY-MM-DD
- 状態: 採用 / 却下 / 廃止（廃止の場合は後継のDを記載）

### 背景
- なぜこの判断が必要になったか

### 決定
- 何を決定したか

### 理由
- なぜその選択をしたか（検討した代替案があれば併記）

### 影響
- この決定が及ぼす影響、制約
```


---

## D-001: 静的サイト＋GitHub への投稿保存で作る

- 日付: 2026-10-31
- 状態: 採用

### 背景
- スマホから最短の手順で投稿でき、外部の有料サービスや停止の心配がない構成が求められた。

### 決定
- サイトは site/ の静的ファイルとし、GitHub Pages で公開する。投稿は /admin/ から GitHub Contents API で site/data/posts.json に保存する（ユーザー選択）。
- X は公式の無料埋め込み、note と YouTube は公開時に RSS を取得する。

### 理由
- Supabase の無料枠は7日間使われないと停止する。Cloudflare はアカウント設定が別途必要。GitHub だけで完結し、投稿の履歴も残る。

### 影響
- 投稿の反映は約1分（公開の待ち時間）。トークンは管理者の端末にだけ保存する。
