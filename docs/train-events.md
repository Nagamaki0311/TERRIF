# 満員電車（仮）イベント60種・実装カタログ

ユーザーの細分化・複雑化の指定を受け、通常50種と特殊10種を実装した。現実の事例・発生率の調査は未完了。名称は車内で想定した現象、条件と点数はゲーム用仮説。カタログ作成時点で出現率・バランス検証は未着手。ユーザーの実装開始指示により初期承認待ちは解除された。従来5種をこのカタログへ置き換える。

## 共通状態と判定語彙

既存の5種族・許容年代・荷物・着席必要・降車駅・stress0～100・4層座標を維持する。追加は次の共通軸にまとめ、個別イベント専用フラグは作らない。

| 軸 | 許容値 | 生成・更新・消滅と表示 |
|---|---|---|
| 行動 | 無/画面/通話/会話/読書/飲食 | 乗車生成で1値、初期版は降車まで固定。駒詳細に短い語で表示 |
| 音 | 静/漏れ | 漏れはイヤホン等の再生音を表す。乗車時生成、固定、音符マークと詳細で表示 |
| 姿勢 | 通常/広げ/寄掛 | 乗車時生成、固定。広げは脚や腕の広がり、寄掛は体重の偏り。表示は姿勢マーク |
| 荷物形式 | 無/背負/手提/車輪 | 既存荷物なしなら無、ありなら後3値のいずれか。固定、詳細で表示。容量は常に1人分 |
| 注意 | 周囲/没頭/居眠 | 固定。居眠は行動=無かつ音=静に限定。詳細で表示 |
| 同行組ID | 無/組ID | 同じ駅で乗る2～3人を最大1組として生成。組は同じ降車駅にし、降車時消滅。線と組番号で表示 |

生成は1回のシード付き乗車生成で行い、未許可の値や矛盾する居眠・行動は生成しない。種族で行動を固定しない。各非空値に非ゼロの試験出現率を割り当てるが、具体率は実装時の調整対象。同行組がない乗客も生成する。移動時は配置だけ更新し、属性再抽選はしない。固定属性により各停車駅で表示が突然変わることを防ぐ。

以下のa,b,c等は互いに異なる乗客。Pは当該行の参加者全員。通常イベントでは共通して、Pの少なくとも1人が当受信waveの伝播により80未満から80以上へ初めて到達していることを必要とする。さらにP全員がその受信直後80以上であることを求める。局所負担だけで80へ到達した駒、既に高いstressだけの放置はイベントを発生させない。追加属性自体のstress効果は増やさず、既存の局所負担と伝播25で閾値を作る。

「隣」は同一特殊区画または共有辺による既存の隣接。「横隣」は同じ層で共有辺、「向い」は北・南立席が共有辺。「着」は着席、「立」は立席、「優」は優先席、「端」は座席帯の最端席。「近出口」は最短距離の南出口、「経路」は既存の降車移動グラフの一意最短経路。「次降」は次駅降車、「残留」は次駅では降りない。「新乗」は現在駅で乗った駒。目的駅まで2駅間以上は「長距離」と呼ぶ。

各行のキーは`通常ID＋sort(Pの乗客ID)`。区画・駅・役割順はキーへ加えず、同じ人の移し替えで再採点しない。役割と位置は判定記録へ残す。全種類各駅間2件まで、全種類合計では1駅間20件まで、各参加者は1駅間1通常イベントまで。合計20件に達した後の候補は不採用とする。候補は基本点降順・種類ID順・参加者ID順で採用し、得点済みキーを永久除外する。採用されなかった候補を次waveへ持ち越して採点しない。全wave共通で予約台帳を更新して重複を防ぐ。

通常点は既存の同時件数・異種数・発生受信waveの式を適用する。50種化による倍率暴騰を防ぐため、件数項はmin(n,10)、種類項はmin(m,5)、深さ項は既存上限2倍で計算する。イベント件数そのものは記録する。基点20～100は、属性数・場所制約・時機・参加人数の多さを目安とした仮値。

## 特殊10種

通常イベント採用後、各受信waveで特殊passを1回実行する。以下は通常イベント履歴と現在の確定候補配置から決まる派生ボーナス。発生後に抽選しない。前提となる通常イベントがすべて採用済みで、今回のwaveで少なくとも1つ新しく採用されたときだけ候補化する。したがって必ず当駅間の連鎖因果を継承する。特殊同士を前提にしない。

通常イベントの参加者制限を特殊に再適用すると成立しないため、別の派生ボーナス台帳を使う。各特殊IDは1プレイ1回、各駅間は特殊2件まで。候補は特別点降順、同点ならID順で採用する。同じ通常イベントキー集合を根拠とする特殊は一つだけとし、異なる根拠集合で同じ通常イベントを再利用することは許可する。採用/除外理由と根拠キーを記録し、特殊点には通常の件数・種類・深さ倍率を重ねない。

## 実装前後の検証と表示

60種類の一覧をプレイ中に読むことは要求しない。操作中は選択駒の属性・配置候補に関係する候補だけを予告し、特殊の組合せ条件も到達見込みがあるときに短く表示する。イベント判定と採点は整数同期waveで完結し、描画と音は同じ履歴を再生する。特殊成立には専用の名称・根拠イベントの連結表示・音の重ね方を設ける。表現仕様はUI・音資料へ委ねる。表示だけのレア演出で実際の採点条件を隠さない。

F01～F60は各IDに対応する到達可能性fixtureとして全件作成する。通常例は当事者の1人をstress60、隣接する発火元を80として受信85を作り、他の当事者を80以上に置く。直接隣接しない同行者は別の発火元を使う。複数特殊の同wave条件は独立した小配置を同じ受信waveへ揃えて構成し、2～3人の扉容量・通常区画1人・南側出口・年代範囲・同行2～3人を守る。各行に使った属性と実際に採用された種類を照合し、高基点の別イベントが先取りして期待イベントを消さないことまで確認する。

境界fixtureは新規閾値到達なし、同組の別役割、他区画への移動、候補競合、種類3件目、同参加者2件目、特殊の根拠集合重複、特殊3件目、200%終了の最終評価、終着降車を含める。カタログ件数・一意IDの静的検査は行うが、これを60種の到達可能性検証と同一視しない。通常・特殊すべてで到達する発見用シードまたは説明付き固定配置を用意する。通常シード群でも出現頻度を測り、特殊が一度も発見できないほど低確率なら属性率や条件を調整する。fixtureや発見用配置の成立だけで通常プレイのレア度を主張しない。

盤面・15駅・200%終了・stress80と伝播25は維持する。イベントによる追加stressは導入しない。50種化によるルール量とUI負荷、特殊の再利用上限、倍率上限、実測頻度、F01～F60の成立確認が今回の追加検証対象となる。

実装時の到達fixtureにより、N23はN04の条件を含む同点イベントとして常に除外されることを検出した。限定条件の多いN23の仮基本点を50に調整し、競合後も全通常種が採用可能となるよう検証する。
