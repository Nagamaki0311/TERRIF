# 満員電車（仮）の操作・連鎖演出・サウンド案

2026年11月24日。実装方針と受入記録。ゲーム係数と採点は train-plan.md、イベント種別と成立条件は train-events.md を正本とし、本書は確定したイベントログをどう操作・提示・再生するかを定める。画面・駒素材・オリジナル音源を実装した。機能検証の結果はprogress.md、主観的な試聴評価は今後の調整対象。

## ユーザー指定と設計の狙い

ユーザー指定は、連鎖から起きるトラブルの件数・種類を攻略の中心にすること、同時連鎖に爽快感と達成感があること、先鋭的で次世代的なUI・UX、厚みがあり気持ちよいサウンド。チープで軽い電子音は禁止。

以下の配色・配置・時間・音量上限は提案値。爽快感は試作操作と試聴で確認する。デザイン判断にはリポジトリの design-principles スキルを適用した。

## 視覚と情報の優先順位

架空の鉄道運行表示と精密な卓上盤面を軸にする。背景は温かい白、構造線は墨色、座席は暗い青緑、選択は明るい青、成立したトラブルは朱色。選択と危険を形・線種・文字でも区別する。平常時のコントラストを保ち、成立の瞬間だけ線幅と局所的な色面を強調する。

数字は等幅数字、和文は読みやすい角ゴシック。駒は独自に作画した人物の顔と肩のSVGを使う。人物の輪郭、衣服、色、種族の一文字を重ねて識別できるようにする。年代は選択詳細に表示する。荷物は輪郭形、着席必要は座席記号、高ストレスは輪郭の刻みで示す。ストレス値は選択時と予告時に表示し、全駒の数値による密集を抑える。

### 駒の小寸法デザイン

| 比較案 | 小寸法での利点 | 課題 | 判断 |
|---|---|---|---|
| 漢字中心 | 1文字で種族を説明できる | 文字を繰り返し読む負担があり、人物らしさが弱い | 一文字の補助表示へ利用 |
| 人物ポートレート | 輪郭と衣服から瞬時に区別でき、乗客という題材が伝わる | 細部を減らして顔を小寸法向けに整える必要がある | 採用 |
| 抽象形 | 単純な輪郭を小さく表示しやすい | 5種族との対応を覚える必要がある | 区画と状態表示へ利用 |

public/tokens.svgのspriteに5種を作成した。youngは角のある髪と黄色のフード、workerは平らな髪と青いジャケット・ネクタイ、elderは丸い白髪と眼鏡・紫の前開き、touristは横に広い帽子と朱色の服・斜めストラップ、restは流した髪と緑の開襟を持つ。形の差を輪郭と肩まで広げ、顔の細かい表情を読み取る必要を抑える。人物像はゲーム上の視覚記号として扱う。

各symbolはviewBox="0 0 64 64"で、IDはyoung、worker、elder、tourist、rest。通常表示は48 CSS pxを基準にする。SVG全体の色変換は行わず、選択は外側の実線、ストレスは外側の刻み、予告は破線に担当を分ける。種族一文字は左下、荷物・着席必要は右側の独立した補助欄へ配置し、人物の顔と帽子を覆わない。年代とストレスの数値は選択詳細で読める。年代別にポートレートを増やさず、同種族の一貫した輪郭を維持する。

画面の優先順位は盤面、次に発生させられるトラブル、次にカオススコアと駅進行。トラブル名は短い日本語、初成立時だけ条件を一行提示する。操作に不要な装飾ラベルは置かない。

## 画面構成と操作

| 領域 | 表示・役割 |
|---|---|
| 上端 | 現在駅・次駅・15駅の進行位置、カオススコア、混雑率、音設定 |
| 中央 | 4層の車両俯瞰、南側の乗降口、優先席、通常立席、扉際の人数 |
| 選択位置の近く | 選択駒の種族・年代・派生属性・降車駅、候補位置の連鎖予告 |
| 下端 | 待機乗客、予告されるトラブル種別と件数、移動残数、取り消し、発車 |
| 評価直後 | 成立トラブルとカオススコアの内訳、今回増えた種類、次駅へ進む操作 |

車両は20,000mmと細長いため、全体表示と操作倍率を用意する。全体表示は駒の分布と出口の関係を読む用途。配置時には選択箇所を拡大し、各対象に44 CSS px以上の操作面積を確保する。全体の小さな駒を唯一の操作入口にせず、待機列・選択詳細・キーボードから対象を選べるようにする。表示上の倍率を変えても区画座標と隣接判定は変えない。

通常操作は「待機駒を選ぶ→候補区画を選ぶ→配置」で成立させる。ドラッグも同じ処理へ接続する。候補を選んだ時点で、その配置を加えた現在の盤面全体について、発火源からトラブル成立までの予告を出す。配置不可の理由はその場に一行表示。発車は待機駒の配置後に有効になる。

キーボードはTabで領域移動、矢印で区画移動、Enterで選択・配置、Escで選択解除。フォーカス対象とスクリーンリーダーへ区画種別・人数・駒・配置可否を伝える。タッチはタップ選択と配置を基本にし、ホバーに依存する情報は選択詳細にも出す。縦画面では待機列と詳細を下部にまとめ、盤面の拡大・横移動を使う。

最初の操作では盤面上の短い案内を段階表示する。案内は「駒を選ぶ」「隣へ置いて反応を見る」「発車して確定」の3段階。チュートリアル中も成立条件と予告の形式を通常プレイと統一する。

## 多種イベントの探索と発見

通常50種・特殊10種の計60種を初期カタログとする承認前提案に対応する。対局中の候補表示は、現在の盤面と選択した配置案で成立可能なイベントに絞る。確定予告と条件不足の候補を区別し、不足条件は当事者・区画・必要な連鎖を一つずつ示す。候補を選ぶと対応する駒と場所だけを盤面で強調し、配置を変えると予告も更新する。

イベント図鑑はプレイから開閉でき、名称・現象・条件語の検索、通常／特殊、既発見／未発見の絞り込みを用意する。既発見は成立条件と前回の成立例を読める。未発見は短い現象のヒントから始め、追加ヒントの表示で必要属性や場所を確認できる。図鑑は閉じても選択駒・配置案・操作倍率を保持する。全件を読むことを配置操作の前提にしない。

特殊イベントの予告には、必要な通常イベントと駒・場所・waveの組合せを因果の順に表示する。成立時も「この通常イベント群から、この特殊イベントが派生した」という接続線と短い名称で説明する。通常イベントの記録と派生した特殊イベントの記録を別のログ種別として保持し、同一の当事者や出来事を参照できるようにする。得点内訳は採点の正本から受け取る。特殊イベントの発生率を装飾的な抽選表示で演出しない。

## 連鎖の時間設計

ルール側は一度だけ計算を確定し、順序付きwaveとトラブルイベントを返す。演出はそのログを再生し、表示中に再計算・再採点しない。ログは評価ID、wave番号、発火駒ID、受信駒ID、トラブル種別・当事者ID・成立wave、採点内訳、通常／派生特殊の種別、派生元イベントIDを持つ。複数の成立条件が同じwaveで満たされた場合は、同時成立の一群として扱う。

| 段階 | 時間の試案 | 視覚・音の役割 |
|---|---|---|
| 発車確定 | 120ms | 候補予告を実際の反応へ切り替え、最初の起点を示す |
| 各wave | 180〜240ms | 同じwaveの発火を同時に強調、隣接への伝播方向を短線で示す |
| トラブル成立 | wave内に同期 | 当事者の位置に種別記号を刻み、短い名称を出す |
| 最終着地 | 350〜500ms | 成立件数・種類をまとめ、得点内訳を確定表示する |

連鎖が深くなるほど反応のまとまりを強くし、終盤へ少し加速する。同時成立は種別記号を一斉に刻み、異なる種類にはそれぞれ固有の形と音の質感を使う。画面全体の拡大や数字の肥大化を繰り返すと配置関係を追いにくくなるため、反応の位置と最後の着地を中心にする。

演出時間は通常1〜3秒、深い連鎖も4秒以内を初期目標とする。長いログは複数waveを短い区間へ束ね、各waveの順序と同時成立のまとまりを保存する。「結果へ」で即座に確定盤面と内訳へ進める。スキップ中の未再生音は捨て、最終着地だけ短く再生する。入力連打でも終了状態と得点は同じになる。

画面振動と強いフラッシュは標準で使わない。prefers-reduced-motionとゲーム内の演出軽減に対応し、短線移動と拡縮を静的な輪郭・wave表示へ置き換える。音を消しても同時成立・種類・得点理由を読み取れる。演出中にタブが隠れたら音を止め、復帰時に結果表示へ進める。

## サウンドの制作方針

音の核は、金属の打撃・木質の打音・摩擦・低い車体共鳴など、物理的な厚みを持つ素材を収録または適切なライセンスで調達し、独自に編集して作る。短い打撃の輪郭と制御した余韻で配置と成立を触覚的に感じさせる。サンプルの加工・重ね合わせを中心に、Web Audioで再生とミキシングを行う。

| 場面 | 音の役割と質感 |
|---|---|
| 駒の選択・配置 | 乾いた近接打音。配置の確定を感じる短い重さ |
| 発車・連鎖開始 | 薄い環境音を少し下げ、共鳴のある短い導入で集中させる |
| 各wave | 同期した打撃と短い低域の胴鳴り。深さに応じて層・密度・音程のまとまりを発展させる |
| トラブル成立 | 種別ごとに識別できる摩擦・打撃・共鳴のアクセント |
| 多種同時成立・着地 | 低域から高域までの一つのまとまった着地。短い残響で達成を閉じる |

通常イベントは圧迫・接触・摩擦・遮断などの共通音色群を持ち、各種別は短いアクセントの組合せと変奏で識別する。60種類それぞれの独立した音源制作は初期コストに含めない。特殊イベントは通常イベントの音色群へ専用の一層を足し、最後にまとまった着地を作る。音色群・変奏・特殊層の対応をカタログIDへ設定し、同じ発生条件は同じ音のまとまりにする。

複数駒が同時反応しても1駒ずつ音を重ねず、wave単位の主音にまとめる。トラブルの種別アクセントを加える際は同時発音数を8声以内に制限し、同系音を間引く。深さによる気持ちよさは密度・音色・和声の変化で作り、音量の上昇は合計3dB以内を試案とする。

環境音は連鎖中に3〜6dB下げる。マスターはリミッターを通し、書き出した素材とミックスの両方でクリッピングを検査する。耳障りな鋭い高域と長すぎる低音の残響を試聴で抑える。群衆の叫びや怒鳴り声を重ねて音圧を稼ぐ表現は採用候補に含めない。低品位なビープや単純なサイン波の単音は使用禁止として制作指示に記録する。

最初のユーザー操作でAudioContextを有効化し、未許可時もゲーム操作を継続できるようにする。効果音・環境音の独立音量と全体ミュートを用意し、設定を保存する。再生時刻はAudioContextの時計を基準にし、同時waveの視覚更新を同じタイムラインへ合わせる。素材の取得元、許諾、加工、帰属表記条件を記録する。実在鉄道の案内音や既存ゲームの効果音をそのまま使う計画はない。

## 実装・受入条件

TypeScriptとVite、DOMとSVGで盤面と操作を構成する。音はWeb Audioとローカル音源を用い、初期版の外部依存を抑える。ローディング、音源取得失敗、配置不可、フォーカス、空の待機列、演出中、結果表示の各状態を作る。音源の読み込み失敗は状態表示と再試行を用意し、入力を失わせない。

承認後、単発・同種同時・多種同時・深い連鎖の4例に、通常イベントから特殊イベントが派生する例を加えて操作可能な試作と音付きで比較する。受入確認は次を満たすこと。

- 図鑑の検索・発見状態・ヒントを使い、60種から現在の盤面に関係する条件を探せる。特殊イベントは派生元の出来事と当事者をたどれる。
- 盤面から成立した場所を追え、内訳から件数・種類・得点理由を説明できる。
- 同じログは通常・スキップ・演出軽減・音なしでも同じ結果になる。
- 同時成立は一群として感じられ、深い連鎖では段階の発展と着地が聞き分けられる。
- 代表的なノートPC内蔵スピーカーとヘッドホンで厚み・高域の疲労・低域の濁り・音割れを試聴する。
- キーボードとタッチで配置、取り消し、発車、結果への移行まで完了できる。
- DOMのテキスト表示とアクセシビリティ検査、ブラウザの音許可・タブ復帰・連打を検証する。

爽快感と先鋭的な印象の完成度は、この試作・試聴で評価する。実装済みの機能検証結果はprogress.mdに記録する。
